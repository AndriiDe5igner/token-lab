# PLAN.md - Token Lab

План на 5 кроків. Кожен крок - окрема гілка `feat/...` і PR у `main`. Після кожного кроку - перевірка в браузері і список того, що перевірити вручну.

Крок 0 (зроблено цим комітом): каркас папок, `.gitignore`, порожній `index.html`.

## 1. Математика кольору - `color.js` + тести
Гілка: `feat/color-math`
- Парсинг і валідація hex (`#RGB`, `#RRGGBB`, з `#` і без), нормалізація до `#rrggbb`.
- Перетворення hex ↔ OKLCH (через sRGB → linear → OKLab). Шкалу будуємо в OKLCH, щоб кроки були рівними на око.
- Шкала 50…950 (11 кроків) для brand: фіксована крива світлості, хрома зменшується до країв, відтінок брендовий. Вхідний колір потрапляє на найближчий крок.
- Шкала neutral: той самий відтінок, дуже низька хрома (легкий тон бренду).
- Вихід за межі sRGB - зменшуємо хрому, поки колір не влізе.
- Контраст WCAG 2.x: відносна яскравість, ratio, рівень AAA / AA / AA Large / Fail.
- Назовні тільки hex і числа, чисті функції.

Готово, коли: `node --test` зелений; тести на #4F46E5, #FACC15, #000, #fff, невалідний ввід, монотонність світлості шкали.

## 2. Екран і свотчі - `index.html`, `styles.css`, `app.js`
Гілка: `feat/ui-shell`
- Потрібен макет у `design/` (скрін з Figma) або посилання на Figma.
- Шрифти Geist + Geist Mono, нейтральний UI, усі кольори UI через змінні в `:root`, сітка, лінії 1px.
- Поле hex + нативний color picker, помилка під полем при невалідному вводі.
- Два ряди свотчів brand / neutral 50…950 з hex під кожним.
- Адаптив від 360px, одна колонка на мобільному, видимий фокус.

Готово, коли: сторінка відкривається локально, шкала змінюється при вводі, помилка показується, на 360px немає горизонтального скролу.

## 3. Семантичні токени і перевірка контрасту - `tokens.js`
Гілка: `feat/tokens-contrast`
- Мапінг шкали на токени: bg, surface, text, text-muted, border, accent, accent-hover, on-accent, danger, success. Світла і темна тема.
- on-accent обирається за контрастом: білий або темний з neutral (для #FACC15 - темний).
- Живе прев'ю: кнопка, картка, інпут у світлій і темній темі, кольори тільки з токенів палітри.
- Бейджі контрасту AAA / AA / AA Large / Fail для ключових пар (text/bg, text-muted/surface, on-accent/accent, border/bg).

Готово, коли: для #4F46E5 і #FACC15 прев'ю виглядає правильно, бейджі збігаються з тестами з кроку 1.

## 4. Експорт
Гілка: `feat/export`
- CSS variables (`:root` + `[data-theme="dark"]`).
- Tailwind v4 `@theme`.
- tokens.json: колекція primitives (brand, neutral) → колекції light / dark з посиланнями на primitives.
- Вкладки форматів, блок коду в Geist Mono, кнопка «Копіювати» + тост «Скопійовано».

Готово, коли: усі три формати копіюються і валідні (CSS вставляється в сторінку, JSON парситься).

## 5. «Поділитися» - D1 + Pages Functions
Гілка: `feat/share`
- `schema.sql`: таблиця `palettes` (id, payload JSON, created_at).
- `wrangler.toml`: name, `pages_build_output_dir = "public"`, `d1_databases` з binding `DB`.
- `POST /api/palettes` - валідація, короткий id (6-8 символів), повертає `{ id, url }`.
- `GET /api/palettes/:id` - віддає палітру або 404.
- `/p/:id` - віддає `index.html`, клієнт підтягує палітру і показує її.
- Кнопка «Поділитися» копіює посилання, тост.

Готово, коли: локально через `npx wrangler pages dev` посилання `/p/...` відкриває ту саму палітру; невідомий id показує зрозуміле повідомлення.
